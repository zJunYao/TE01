# UI、事件与资源生命周期

核实日期：2026-10-26。来源：[UI 实现目录](../../UnityProject/Assets/GameScripts/HotFix/GameLogic/Module/UIModule/)、[事件实现目录](../../UnityProject/Assets/TEngine/Runtime/Core/GameEvent/)、[资源实现目录](../../UnityProject/Assets/TEngine/Runtime/Module/ResourceModule/)。

## UI 接口与生命周期

- `UIWindow`、`UIWidget` 是 C# UI 对象，不是直接挂到 Prefab 的 MonoBehaviour；根资源需满足 RectTransform、Canvas 等实现要求。
- `[Window(UILayer.UI, location: "资源地址")]` 控制层级、资源地址、全屏及隐藏关闭时间；地址为空默认类型名，默认隐藏关闭时间为 10 秒。
- `GameModule.UI.ShowUIAsync<T>(params object[])` 返回 `void`，只发起异步打开；同步入口 `ShowUI<T>` 也存在。
- `ShowUIAsyncAwait<T>` 返回 `UniTask<T>`；`GetUIAsyncAwait<T>(CancellationToken)` 只查已有窗口，不负责打开。
- `CloseUI<T>` 关闭并移出栈；`HideUI<T>` 隐藏但保留实例和事件，启动延时关闭；`HideTimeToClose <= 0` 时立即关闭，不能用负值表示永久缓存。
- 一个窗口类型通常复用栈中的同一实例，重复 Show 会提到栈顶并更新 UserDatas；不能按多实例窗口 API 使用。

创建顺序：资源就绪 → `Inject` → `ScriptGenerator` → `BindMemberProperty` → `RegisterEvent` → `OnCreate` → `OnRefresh`；再次显示主要重新刷新，不重新注册整套事件。

生命周期回调是 protected virtual，不要写成 public override；没有 `OnClose` 回调。窗口显示/遮挡通知用 `OnSetVisible`，轮询用 `OnUpdate`，销毁清理用 `OnDestroy`。

Window 可见性主要通过 Canvas 所在 Layer 与 Raycaster 管理，并非简单 SetActive；Widget 的 Visible 使用 SetActive。Window 隐藏时不更新，但 Widget 的 `InternalUpdate` 本身没有按 Visible 拦截，不能假设局部 Widget 关闭激活后逻辑轮询必定停止。

Widget 支持绑定已有节点、Prefab 克隆、资源地址/类型创建；主动销毁调用 `Destroy()`，由父列表和递归清理处理，不手动调用内部 `OnDestroyWidget`。绑定现有节点的 Widget 也会在销毁路径销毁该节点，不能假定只解除 C# 绑定。

### 等待接口限制

当前 `ShowUIAsyncAwait` 对已有窗口直接返回，已有窗口仍加载时不保证准备完成；新建分支按 `Time.deltaTime` 累计到 60 秒后也返回窗口，而非统一抛超时异常。`GetUIAsyncAwait` 同样有超时后返回的路径。业务不能仅凭 await 返回就假设 Prefab 绑定已成功，需检查 `IsPrepare`、对象有效性和任务取消语义。

## 事件系统

- 业务事件接口用 `[EventInterface(EEventGroup.GroupUI/GroupLogic)]`，方法保持简单 void 回调签名、名称唯一，避免重载等生成器未明确支持的设计。
- [生成器源](../../Tools/GameEventSourceGenerator/SourceGenerator/Generator/EventInterfaceGenerator.cs) 生成 `接口名_Event` 的 ID、`接口名_Gen` 包装器、`GameEventHelper.Init` 和 AddEvent/RemoveEvent 辅助方法；不要手写或持久化 int 事件 ID。
- `RuntimeId` 是按进程中首次注册顺序递增的字符串映射，不是稳定跨进程哈希，不用于存档、网络协议编号。
- `GameEventHelper.Init()` 注册接口包装器后，才可通过 `GameEvent.Get<T>()` 发事件。重复初始化会触及字典重复添加，不能无条件重复调用。
- `GameEvent` 底层保留 int/string 监听与发送；规范鼓励接口事件，不代表旧重载不存在。
- UI `AddUIEvent` 支持 int ID 的 0～4 参数版本，泛型版本为 protected；`GameEventMgr` 本身另有五参数版本，不等于 UIBase 已暴露。
- `GameEventMgr` 从内存池归还时 Clear 逐项退订；窗口/Widget 销毁链调用清理。隐藏不退订，应在回调中考虑窗口状态。
- 非 UI 订阅者必须保存同一委托用于退订，避免无法退订的临时 lambda；不要把全局 `GameEvent.Shutdown` 当成局部清理手段。

## 资源三种归属

### 普通 Asset

`LoadAsset<T>`、`LoadAssetAsync<T>(location, cancellationToken=default, packageName="")` 返回资源本体。每次成功获取的池引用应配对 `UnloadAsset(asset)`；后者是 Unspawn，不保证立刻释放底层句柄。

原始 `GetHandleSync/GetHandleAsync` 等句柄接口绕过普通托管引用的使用方式，由调用者按实际 YooAsset 句柄契约释放，不能混用两套所有权。

### 实例资源

`LoadGameObjectAsync(location, parent=null, cancellationToken=default, packageName="")` 返回实例，内部挂接 `AssetsReference` 记录源 Prefab。销毁实例时归还源引用，不要再把实例当作普通 Asset 调用 UnloadAsset。

手工 LoadAsset 后 Instantiate 必须自行保管源资源引用或正确挂接引用组件；不能只销毁克隆就认定源资源自动释放。也不要无审查地二次克隆带有引用记录的实例。

### Sprite 设置

`Image.SetSprite(location, setNativeSize=false, callback=null, cancellationToken=default)` 和 SpriteRenderer 重载返回 `void`。扩展负责请求替换、赋值和缓存引用；不虚构 `SetSpriteAsync/ReleaseSprite`。

同目标新请求取消旧请求，并核对当前请求身份。资源释放检查依据目标销毁、sprite 清空或被替换，不以 GameObject 隐藏为释放条件；释放是周期/分帧检查，不是立刻发生。需要及时解除引用时应考虑清空 sprite，再由扩展清理。

## 取消与失败不是统一契约

ResourceModule 的新加载分支用 `SuppressCancellationThrow`，取消可释放句柄后返回 null；空地址可能抛异常，非法地址可能日志后返回 null。缓存命中及等待同地址加载的路径未一致传播 CancellationToken，因此不能承诺“取消后绝不创建实例”或“所有失败必抛异常”。

调用后检查 null 和宿主生存期，明确迟到资源如何销毁/归还。UIWindow 的内部资源加载没有统一接入业务 CancellationToken，而是通过 IsDestroyed 处理迟到实例，不能凭接口名假定全链路可取消。
