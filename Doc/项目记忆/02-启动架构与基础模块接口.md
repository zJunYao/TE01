## 模块机制

- 当前 `Module` 是普通 C# 抽象类，不是 MonoBehaviour；核心入口是 `Priority`、`OnInit()`、`Shutdown()`。帧更新由 `IUpdateModule` 单独表达。
- `ModuleSystem.GetModule<T>()` 要求模块接口，按接口名称去掉首字符 `I`，在同程序集查找实现并反射创建；不是任意业务依赖注入容器。
- 模块按优先级降序轮询，关闭时反序处理；添加模块时必须核实命名、程序集和初始化依赖。
- `GameModule` 缓存 Base、Debugger、Fsm、Procedure、Resource、Audio、UI、Scene、Timer、Localization。`Base` 查找场景 RootModule；`UI` 取 `UIModule.Instance`，其他多走框架模块系统。
- 当前没有 `GameModule.ObjectPool` 属性，也没有 `IUIModule`。`GameModule.Shutdown()` 本身是清空门面缓存，不等于关闭所有框架模块。
- 业务 `SingletonSystem` 挂接 `IUpdateDriver`，维护 Update/FixedUpdate/LateUpdate 等列表；释放时退订驱动。不要将其与框架 `IUpdateModule` 混为同一个接口。

## 启动与热更边界

1. `GameEntry.Awake()` 先取得 UpdateDriver、Resource、Debugger、Fsm，再调用 `Settings.ProcedureSetting.StartProcedure().Forget()`，入口对象跨场景保留。
2. 主要流程为 Launch → Splash → InitPackage → InitResources。资源版本、清单、下载决策受运行模式和边玩边下配置影响。
3. 下载分支进入 CreateDownloader/DownloadFile/DownloadOver 等状态；DownloadOver 的 `_needClearCache` 默认 false，不能描述为必经 ClearCache。
4. Web/边玩边下等分支可直接进入 Preload，后续 LoadAssembly → StartGame。
5. LoadAssembly 按条件编译与资源配置加载程序集/AOT 元数据，通过反射调用全局 `GameApp.Entrance(object[])`；参数包装内包含 `List<Assembly>`。
6. `GameApp.Entrance` 先 `GameEventHelper.Init()`，保存程序集列表并挂接释放；当前直接打开 `BattleMainUI`，Login 打开调用被注释。

`GameEntry`、Procedure、Launcher 为主包；热更业务在 `HotFix`，实际边界以 `GameLogic.asmdef`、`GameProto.asmdef` 及引用关系为准。条件 `ENABLE_HYBRIDCLR`、`ENABLE_OBFUZ` 的存在，不证明当前平台热更或混淆链路已配置并验证。

## 基础接口速记

### FSM 与流程

- `IFsmModule` 提供按持有者类型和名称创建、查找、枚举、销毁状态机；`IFsm<T>` 提供 `Start`、状态查询、数据读写。
- `FsmState<T>` 回调为 `OnInit/OnEnter/OnUpdate/OnLeave/OnDestroy`，通过其 protected `ChangeState` 切换；不要想当然调用 `IFsm<T>.ChangeState`。
- `ProcedureBase : FsmState<IProcedureModule>`，流程不是另起一套 MonoBehaviour 生命周期。

### 内存池与对象池

- `MemoryPool.Acquire<T>()` 要求 `class, IMemory, new()`；`Release(IMemory)` 时清理并归还，`IMemory.Clear()` 必须解除旧引用和状态，不能重复回收后继续使用。
- `IObjectPoolModule` 创建 SingleSpawn/MultiSpawn 池；`IObjectPool<T>` 要求 `ObjectBase`，用 `Register(obj, spawned)`、`Spawn`、`Unspawn`、`ReleaseAllUnused` 等管理。
- `Unspawn` 表示归还使用计数，不等于立即销毁；真正释放受锁定、容量、过期、优先级和过滤规则影响。资源池使用 MultiSpawn。

### 计时器

准确签名：`AddTimer(TimerHandler callback, float time, bool isLoop = false, bool isUnscaled = false, params object[] args)`，返回 int ID；回调接收 `object[]`。

有 Stop、Resume、Restart、ResetTimer、RemoveTimer、GetLeftTime 等；`RemoveTimer` 先标记后在更新中移除，宿主销毁时应主动取消。循环计时器应传正间隔，当前补帧逻辑递归追赶，不要传零/负循环间隔。

`AddSystemTimer` 返回 `System.Timers.Timer`，不是 Unity 主线程计时器；不可在其回调直接操作 Unity 对象。

### 场景

`ISceneModule` 提供 `LoadSceneAsync`、回调型 `LoadScene`、`ActivateScene`、`UnSuspend`、`UnloadAsync/Unload`、场景查询。参数名为 `progressCallBack`，接口没有 CancellationToken 参数。

主场景和附加场景分别管理，卸载接口针对记录的附加场景；挂起加载需要其他逻辑调用 `UnSuspend`，不能先等待挂起操作完成再解挂。并发/失败恢复需额外审查当前 `_handlingScene` 路径，不能假定自动重试安全。

### 音频、本地化、调试与驱动

- `IAudioModule.Initialize(AudioGroupConfig[], Transform, AudioMixer)`；`Play(AudioType type, string path, bool bLoop=false, float volume=1, bool bAsync=false, bool bInPool=false)` 返回 AudioAgent，默认不是异步或常驻池；提供分类开关/音量、Stop/StopAll 和片段池管理。
- `ILocalizationModule` 提供 Language/SystemLanguage、LoadLanguageTotalAsset、LoadLanguage、CheckLanguage、SetLanguage 的不同重载；大部分本地化细节在集成实现中，不能仅凭语言设置成功推断字体、资源已验收。
- `IDebuggerModule` 及窗口接口用于运行时调试面板；扩展时按实际窗口注册/更新/绘制契约，不作为业务网络或数据服务。
- `IUpdateDriver` 提供帧、销毁、暂停等监听注册/移除，也保留 Coroutine API；新业务仍遵循 UniTask 规范。
- 网络模块中文文档目前仅占位，不能虚构已经存在的业务网络连接/协议模块。
