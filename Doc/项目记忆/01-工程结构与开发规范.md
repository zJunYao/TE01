# 工程结构与开发规范

核实日期：2026-10-26。规范源：[仓库 AGENTS](../../AGENTS.md)、[Unity AGENTS](../../UnityProject/AGENTS.md)、[工作流指南](../../Books/AI-Development-Workflow.md)。发生冲突时重新核实源码与实际工具能力。

## 目录定位

- `UnityProject/Assets/GameScripts/GameEntry.cs`、`Procedure/`、`Assets/Launcher/`：主包启动层。
- `UnityProject/Assets/GameScripts/HotFix/GameLogic/`：热更业务、UI、业务单例；`GameProto/`：协议/配置及 Luban 基础库位置。
- `UnityProject/Assets/TEngine/Runtime/`：框架核心、模块；`Editor/`：编辑工具；`Extension/`：HTML 转 UGUI、输入扩展等。
- `UnityProject/Assets/AssetRaw/`：资源源目录；地址定位与收集规则需查看实际 YooAsset 配置，不能假设磁盘路径等同于资源地址。
- `Configs/GameConfig/`：Luban 结构、Excel 数据、模板及导出脚本。
- `Tools/`：Luban、事件代码生成器、文件服务等；不是 Unity 项目 CLI 所在位置。
- `Books/`：项目中文说明；历史示例存在漂移，不能直接复制作为当前 API。
- `Doc/开发阶段文档/`：需求、设计、开发与验证过程；`Doc/项目记忆/`：长期项目知识。

## 工作约束

- 中文沟通和交付；先读相关实现、调用方与 `git status`，保留现有修改，不恢复用户删除的文件。
- 普通源码修改按任务实施；跨模块、高风险、多阶段任务用一份任务文档记录目标、验收、决策、授权、证据。
- Unity 写入先预览具体目标与范围，再集中确认；删除、覆盖、依赖/项目设置、平台切换、真实构建须明确专项授权。
- 不自动安装或升级工具，不自动提交、推送、上传、签名、发布，不修改用户级技能。
- 不使用 Unity MCP 或旧规范管理工具；本项目 Unity 状态、序列化和资源数据库操作使用项目 CLI。
- 不手写 Scene/Prefab YAML、GUID 或 `.meta`；源码用代码编辑工具，`.meta` 由 Unity 生成。
- 不读取到日志或分享 Pipeline 鉴权描述，不借用其他工程的连接进行验证。

## 规范中的开发取向

- 业务模块访问走 `GameModule`，框架启动保留既有初始化方式。
- 业务 IO 异步用 UniTask，明确失败、取消、销毁竞争和资源所有权；框架现存同步 API、Coroutine 仍客观存在。
- UI 用 `AddUIEvent` 管理监听；非 UI 对象维护自己的退订。关闭、隐藏、资源释放不是同一动作。
- 生成类问题先追溯源模板，不只手改下一次就会被覆盖的产物。

## 验证入口与选择

从仓库根可运行：

```powershell
python UnityProject/.codex/scripts/workflow.py --help
python UnityProject/.codex/scripts/workflow.py verify --profile docs
```

- `docs`：文档与工作流检查，不连接 Editor；纯文档任务不必启动 Unity。
- `code`：包含文档检查和完整解决方案构建。
- `unity`：Editor 编译、指定资源与明确测试集；先发现用例，零执行、全部跳过不算通过。
- `full`：组合检查，并包含配置和浏览器回归等额外依赖。
- CLI 路径为 `UnityProject/Tools/unity.exe`，不是安装目录的 Unity Editor。环境、命令、包能力以本项目实际结果为准。
- 忙、断开、多实例、依赖缺失都如实报告阻塞；写入超时代表结果未知，不能自动重放。

`.codex/runs` 存本地验证证据，`tasks` 存任务记录，`templates` 是任务模板，`evals` 是 AI 工作流评估场景；这些不是游戏运行代码。
