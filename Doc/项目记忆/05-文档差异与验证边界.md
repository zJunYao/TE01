# 文档差异与验证边界

核实日期：2026-10-26。下面是后续工作应记住的限制，不是本次已经修复的缺陷列表。

## 已核实的文档漂移

1. Books 中仍有 `ModuleImp`、MonoBehaviour 型 Module、`GameScripts/Main` 等历史表述；当前是普通 C# Module 与实际 GameEntry/Procedure/HotFix 目录。
2. 部分 UI 注释称返回“句柄”，但 `ShowUIAsync/ShowUI` 实际返回 void；等待方法另有命名，且复用/超时语义有限。
3. UI 生命周期没有 OnClose；隐藏期间仍保留事件，默认延时关闭。不能照搬其他框架的 OnShow/OnHide/OnClose 模板。
4. 配置技能描述分片导出，而实际 lazyload 脚本与模板仅实现普通 bin 的按表懒加载；工作流回归对 ClearPartitions 的期待与此不一致。
5. AI 工作流指南的 Unity 6000 等是上游维护基线；本工程现已适配到 `2022.3.62f1`，版本以 ProjectVersion.txt 和本地依赖为准，不按文档自动升级。
6. 网络章节仍是占位，不代表已有网络业务模块；平台截图索引也不证明当前工作区在那些平台完成运行验收。

## 静态阅读发现的使用风险

- UI 等待接口在复用尚未加载窗口时可能立即返回；超时也可能返回未准备对象。详见 UI 主题，不把 await 等同于成功。
- 资源加载的缓存与新加载路径对取消处理不一致，应检查迟到实例、空返回、宿主销毁和引用配对。
- ConfigSystem 模板加载 TextAsset 后无明确 UnloadAsset；这是模板中的待审查资源归属，不代表已经证明实际游戏持续泄漏。
- SceneModule 的异常与提前返回不总是 finally 清理处理标记；回调型 Unload 中可见两次 `UnloadAsync()` 调用。后续修改场景逻辑时需做专门测试，本次没有修复或运行复现。
- TimerModule 循环补帧会递归追赶，零/负循环间隔存在失控风险；业务应使用正间隔。系统 Timer 回调也不是 Unity 主线程。

这些结论来自具体分支的静态阅读，不能扩展为整个框架已经完成安全、并发、性能审计。
