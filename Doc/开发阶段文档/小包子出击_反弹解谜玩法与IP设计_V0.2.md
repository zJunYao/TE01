# 小包子出击：反弹解谜玩法与 IP 设计 V0.2

> 更新日期：2026-10-26。
> 本文汇总当前讨论方向和 Demo 实现状态，替代 V0.1 的累计得分弹珠台定位。
> “小包子出击”“馊馊怪”等均为工作名称，未进行正式命名、商标或商业发行审查。
> 下文严格区分：已确认方向、当前原型规则、未来提案和待确认事项。原型参数不是正式平衡定案。

## 一、方向总结

### 1. 核心定位

一款以**有限次弹射、反弹路线、破坏障碍和机关联动**为核心的轻度物理解谜闯关游戏。

玩家从固定位置发射食物角色，通过角度和力度安排路线，净化关卡中的怪物。飞行期间不操作挡板，也不控制角色运动；上一轮发射改变的台面状态，会影响下一轮的选择。

**一句话概括：小包子和食物伙伴，用弹跳与反弹夺回被馊馊怪占领的家园。**

### 2. 已确认的方向

- 采用“反弹解谜弹珠”，不再以长时间持续弹跳、累计目标分为主玩法。
- 借鉴有限发射、物理反馈和跨发射改变布局的通用设计，不使用《愤怒的小鸟》的角色、美术、名称或具体关卡。
- 食物是有性格的可爱角色，而不是一次性消耗品。
- IP 朝可爱、原创、可长期扩展发展；目前以“小包子对抗馊馊怪”验证角色表现。
- 技术继续使用 Unity 2D 物理，不切换到 3D。

### 3. 与 V0.1 的关键变化

- **通关：**从累计分数达到门槛，改为清除本关全部必需目标；画面表达为“净化馊馊怪”。
- **决策：**从连续碰撞收益，转为角度、力度、发射顺序与路线利用。
- **回弹：**保留可预判的墙面反弹，移除持续补充球速的自动回弹器。
- **资源：**有限出击机会；Demo 只保留一种普通角色，不直接沿用三球种资源系统。
- **状态保留：**保留已完成的净化、障碍破坏和开门状态；重试恢复全部状态。
- **分数：**当前仍显示反馈数字，主题命名为“香气”，不作为通关条件；是否参与正式评级待确认。

## 二、核心循环与胜负

1. **观察关卡：**辨认馊馊怪、可破坏障碍、开关、封条和反弹边界。
2. **准备出击：**在固定发射点调整角度、力度；准备过程不扣次数。
3. **发射：**真正生成角色并赋予初速度时，扣一次出击机会。
4. **自动运动：**角色在重力与碰撞下运动，命中敌人、破坏障碍或触发开关。
5. **回收与结算：**角色离场或满足安全回收条件后回篮休息，播放短反馈，再决定下一次出击或胜负。
6. **重试：**恢复敌人、障碍、门、开关、分数和次数；不恢复成随机新布局。

### 当前 Demo 的胜负规则

- 净化全部 3 个馊馊怪后，等待当前角色结束运动，再显示成功。
- 用尽出击机会，但当前角色仍在运动时，不提前判失败。
- 当前角色结束后，若仍有馊馊怪且次数为零，显示失败。
- 飞行中、结算缓冲期间以及成功或失败后，不允许重复发射。
- 可以随时重新挑战，包括飞行过程中。

**未来若加入多角色同场、动态倒塌或延时连锁，需要重新定义稳定判定；当前 0.6 秒缓冲不等于通用的物理稳定检测。**

## 三、IP 与表现原则

### 1. 世界与冲突

当前原型发生在“早餐角”。馊馊怪占领厨房空间、堵住路线，让原本香喷喷的环境失去活力。食物伙伴通过弹跳行动净化它们，恢复家园。

未来可扩展厨房、甜点工坊、冰箱、野餐花园等区域，但这些只是世界观提案，尚未实现。

### 2. 小包子：当前唯一可操作角色

- 圆润身体、头顶包子褶、奶油白与粉色脸颊，建立识别点。
- 性格建议：热心、勇敢，有一点冒失；当前通过表情与动作传达，不包含剧情系统。
- 已实现待命、飞行、碰撞、庆祝四张表情。
- 飞行时轻微倾斜，碰撞时眯眼并挤压；只改变视觉子物体，不改变碰撞体。
- 出击结束表现为安全回到软篮子休息；消耗的是本关行动机会，不是角色生命。

### 3. 小馊团：当前基础敌人

- 淡紫色软绒球、小短脚、卷毛、顽皮表情，不采用写实腐败或霉斑。
- 当前一击净化，不重复计数。
- 命中后短暂惊讶挤压，紫色本体直接膨散淡出，伴随紫色烟团散开；不出现绿色本体。逻辑仍称为“净化”，判定即时完成，消散动画由独立替身播放。
- 不使用流血、尸体和恐怖表现；“净化”是视觉与叙事表达，不代表已实现敌人转友军系统。

### 4. 长期扩展原则

- 先建立主角辨识度，再扩充食物伙伴，不先堆大量只有外观差异的球。
- 食物保持新鲜、干净、可爱；不要把受损、打碎食物作为主要快感。
- 敌人可以通过装备和行为扩展，尽量不靠单纯增加血量制造难度。
- 小土豆重击角色、小豌豆伙伴分裂角色，以及罐罐馊、贪睡馊，均为**待验证提案**，不是已实现或已定完整规则。
- 小豌豆若采用分裂，应优先解释为召唤同伴，不表现为身体破碎。

## 四、当前单关布局与交互

### 1. 关卡目标

用 3 次出击，净化全部 3 个小馊团：中部一个、左侧饼干板后一个、右上点心盒凹槽内一个。

### 2. 场景对象

- **小馊团：**命中一次净化，香气增加 100；不因重复接触重复领取。
- **饼干板：**阻挡左侧路线，碰撞相对速度达到 2.5 时破坏；低速接触不破坏。当前为静态障碍，破坏后隐藏并播放碎屑色光点，不是动态木架倒塌。
- **香气开关：**左上金色圆钮，首次命中变绿，解除右上点心盒封条；激活状态保留。
- **点心盒封条：**金色横条，未开门时阻挡入口，不能靠碰撞直接打碎。
- **边框与导流板：**不可破坏，用于借力反弹；当前视觉为薄荷绿色简化几何结构，尚非完整厨房美术。
- **软布回收篮：**底部的回收表现；底部出口触发器与越界检查负责实际回收，不是可碰撞的封闭地板。

### 3. 跨发射保留

同一挑战内，净化结果、饼干板破坏、开关激活、封条开启、香气与剩余次数都保留。重新挑战时全部恢复初始状态。

## 五、操作与临时参数

### 操作

- 发射点附近按住鼠标向后拉，反方向决定发射角度，距离决定力度，松手发射。
- 在发射点上方拉动或拉动不足时松手，取消拖拽，不扣次数。
- 也可使用角度、力度滑条，点击“包子出击”。
- A / D 或左右键调角度，W / S 或上下键调力度，空格发射，R 重试。
- 当前按桌面鼠标键盘原型验收；专门的移动端触摸、屏幕安全区与手势体验未完成验收。

### 临时参数（不是正式玩法定案）

- 出击机会：3 次。
- 最大发射初速度：15；力度范围：35%～100%。
- 发射角度：15°～165°，右方水平为 0°、逆时针计算。
- 重力倍率：0.65；墙面与角色弹性：0.78；空气阻力参数：0.06。
- 饼干板破坏阈值：碰撞相对速度 2.5。
- 低速停滞 3 秒、飞行达到 20 秒、底部或横向越界时回收。
- 回收后结算缓冲：0.6 秒。
- 香气：每个小馊团 100，当前只作反馈，不是独立经济资源。

引导线只显示带重力的初始轨迹，到第一次实体碰撞停止，不预测连锁反弹；当前不纳入空气阻力修正，因此不应宣传为精确轨迹。

## 六、实现入口与素材

- 运行场景：`Assets/Scenes/PinballDemo.unity`。
- 场景入口物体：“小包子出击原型”。运行时生成台面、摄像机、主方向光及界面。
- `Assets/Pinball/Scripts/PinballDemo.cs`：布局、发射、状态、界面与角色资源。
- `Assets/Pinball/Scripts/PinballBall.cs`：2D 物理运动、碰撞回调与回收。
- `Assets/Pinball/Scripts/PinballSurface.cs`：敌人、障碍、开关和门的交互及重置。
- `Assets/Pinball/Scripts/FoodCharacter.cs`：角色表情、呼吸、挤压、净化和回篮动画。
- `Assets/Pinball/Scripts/PinballImpact.cs`：短生命周期碰撞光点与火花。
- `Assets/Pinball/Scripts/FoodFeedback.cs`：分材质碰撞反馈、坏味道烟团、饼干碎屑、香气联动与程序合成占位音效。
- `Assets/Pinball/Scripts/BunRollVisual.cs`：位移驱动的身体与包子褶轻滚、独立可读脸部、接触阴影和擦边侧摆；纯视觉近似，不改变重力和刚体运动。
- `Assets/Pinball/Resources/食物原型/`：4 张小包子表情、3 张小馊团表情、1 张饼干板贴图。
- `Tools/生成食物原型素材.py`：使用 Pillow 在本地绘制素材，无外部 IP 素材、网络或付费生成接口。
- 操作与验收说明：[《基础弹珠原型说明》](../Pinball/基础弹珠原型说明.md)。

运动采用 `Rigidbody2D`、`CircleCollider2D`、`BoxCollider2D`、`PhysicsMaterial2D` 与连续碰撞检测；角色为精灵显示。拖尾不改变 2D 物理方案。当前界面使用原型级即时模式 GUI，未接入正式 UI 流程或关卡配置系统。

## 七、验证状态与已知限制

### 已验证

- 最终脚本使用 Unity 2022.3 编译器检查通过，未产生编译告警或错误。
- 在隔离 Unity 2022.3 项目中运行真实 2D 物理模拟，验证素材加载、关卡有解、成功禁发、失败禁发、重复发射保护、结算缓冲和重试恢复。
- 在 0.02 秒物理步长下，参考解为第一球约 102°、70% 力度，第二球约 68°、70% 力度；用于证明该布局有解，不作为所有参数环境下的保证。
- 检查过摄像机渲染的台面截图，确认角色和场景基础显示。

### 尚未验证或实现

- 未完成完整交互录屏、逐帧动画、不同屏幕尺寸和实际手感的人工验收；摄像机截图不包含即时模式 GUI。
- 未实现土豆、豌豆、多球、敌人护甲、动态支撑、结构倒塌和炸药连锁。
- 未实现关卡选择、正式评级、成长收集、存档、商业化和正式音效系统；已增加限流、轻微变调的程序合成原型音效，尚未完成人工试听与正式混音。
- 当前美术为本地绘制的可替换原型素材，不是正式商业美术或已完成的品牌视觉规范。
- 当前布局在代码中生成，尚未改成可视化编辑或数据驱动关卡。

## 八、后续优先事项（建议，未授权即开始实施）

1. **先验收当前角色体验：**小包子在实际运动尺寸下是否清晰可爱，馊馊怪是否好认，净化和回收是否容易理解。
2. **打磨发射手感：**拖拽区域、力度反馈、镜头与界面可读性；明确轨迹引导精度。
3. **制作少量不同解法的关卡：**分别验证直达、借墙反弹、破障、先开门后收尾，不只移动目标位置。
4. **确定结束规则：**是否保留 20 秒安全回收，是否需要主动结束本次出击，未来动态结构如何判稳。
5. **再验证一个新食物角色：**土豆或豌豆二选一，不同时扩展大量系统；完整定义能力、资源和碰撞交互。
6. **完善 IP 规范：**正式命名、主角比例、色板、表情、故事关系和素材权属审查。

> 当前核心：用可爱的食物角色承载有限次反弹解谜，让每次出击产生可理解、可保留的局面变化。
